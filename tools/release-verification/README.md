# Independent published release verification

`releases.json` selects exact stable PHP versions and full source commits. The hosted
workflow observes their tag, merged PR, release workflow, Packagist source/dist and
original archive. It compares every archive file to the Git object, validates the
complete Git export inventory, released v2 handoff and all three canonical manifests
against their pinned authoritative schemas, runs the unchanged package's complete
check and security audit, and installs the original ZIP without development
requirements. It removes vendor and replays the same lock using an isolated,
warmed, read-only Composer cache with network disabled before loading every runtime
export and running the shipped examples. Every declared canonical API symbol must
be present in the installed classmap at its declared unchanged source file; only
the SDK's two documented optional PHPUnit bridges defer loading in a no-dev consumer.
The consumer's own dependency graph receives an online security audit before replay.

The SPDX source inventory and in-toto verification statement are generated by this
independent verifier. They describe the unchanged published source and observed
verification. They do not claim to be publisher build provenance or to verify a
native binary, App integration, or every other package in the extraction graph.
Native releases require their additional ABI, platform, binary and signed publisher
provenance gates. `tools/verify-package-set-consumer.php` separately qualifies the
complete selected PHP graph after all source archives have independently passed.

A failed gate uploads a failed diagnostic envelope. Only a passing hosted run can
create `RELEASE-ATTESTATION.yaml`, after the evidence envelope has its actual GitHub
artifact URL. The YAML is uploaded in a second artifact, so it contains no digest of
itself. Consumers record that second immutable artifact URL, its ZIP SHA256, the
`RELEASE-ATTESTATION.yaml` member and its separate SHA256. GitHub artifacts are retained
for 90 days; consuming change-set evidence must preserve the downloaded envelope and
attestation before retention expires. No released source, tag or release is mutated.

Run the verifier with PHP 8.5, Composer, Git and Node (with the locked npm dependencies):

```sh
npm ci --prefix tools/release-verification --ignore-scripts
node tools/release-verification/test-verifier.mjs
node tools/release-verification/verify-release.mjs verify coordinate.json output
```

The bundled handoff schema is the v2 schema from Kumwe App, used read-only. The
selected released handoff remains authoritative; mutable chat claims cannot supply
missing evidence. Local passing checks remain local evidence and cannot finalize a
hosted attestation.

## Stable native fixtures and the two complete graphs

`native-releases.json` stays `null` until actual independently verified stable Engine
and binding releases have durable evidence. Its eventual schema is
`kumwe-verified-native-selection/v1`, with `engine` and `extension` entries containing
`name`, `version`, `source_commit`, the **published compressed** `archive_sha256`,
`attestation: {zip_uri, zip_sha256, member, member_sha256}`, and
`evidence: {zip_uri, zip_sha256, verification_member}`. The members are respectively
`RELEASE-ATTESTATION.yaml` and `verification.json`. ZIP URIs must identify an immutable
SDK Git commit under `evidence/`; preserved bytes and the original hosted artifact
URIs remain recorded there. This evidence tree is excluded from package archives.

`materialize-native-evidence.mjs` checks the original ZIP/member hashes, complete
external receipt schema, source coordinates, all five previously verified publisher
signature subjects, complete evidence inventory, full schema/source verification and
actual network-isolated build records. It matches both owners' raw embedding TAR
identity separately from the published compressed Engine archive, then builds a fresh
fixture using the unchanged binding source. Signature verification itself belongs to
the upstream native verifier; this stage validates its preserved evidence and bytes.
The fresh expected full Runtime tuple is derived from source/build metadata before
querying the module, because build host metadata can vary between valid builds.

The generic PHP verifier accepts an optional qualified fixture JSON only when the
actual source runtime/development requirements need it. PHP overrides apply solely
to those subprocesses. SDK's original production ZIP consumer and the complete
portable graph still run with the original native-free PHP. Native Computation's
source and production consumer use the verified stable fixture.

`releases.json` selects the 31-package portable graph with Computation 0.1.1.
`native-php-releases.json` stays empty until the independently published native
Computation 0.3.1 can be selected. Once populated, the workflow verifies that additional
archive and builds a separate 31-package native graph by replacing only Computation.
Both modes perform a fresh no-dev authoritative install and a second installation
from the unchanged lock with network disabled. The native mode also checks the actual
module's full expected tuple and native adapter behavior. Neither mode claims App
integration or qualifies an unselected future release.
